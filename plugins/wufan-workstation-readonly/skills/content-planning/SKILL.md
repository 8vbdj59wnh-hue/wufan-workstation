# 内容策划与下周需求

通过极简工作站正式内容中心完成策划。只使用本插件提供的工具，不连接数据库、服务器文件或 SSH。

## 工作顺序

1. 用 `get_content_product_selection` 按品牌精确读取选品确认、内容账号和固定栏目。
2. 用 `list_content_column_schedule` 读取目标周及相邻日期的排期和已保存需求；分页读完相关结果。
3. 结合用户在当前任务中提供且当前可访问的参考资料策划内容。无法访问参考文件时明确说明，不猜测其内容。
4. 按账号、栏目、日期、主题和产品检查重复与排期空缺。只能关联选品确认返回的产品 ID。
5. 已有对应空白需求时，读取原记录 ID、revision、账号、栏目、日期和时间，展示补填对应关系；使用 `fill_next_week_requests` 补填，不能另建占用同一排期的需求。仅在没有对应需求且确认排期空缺时使用 `save_next_week_requests` 新增。
6. 用户在当前请求中明确要求或授权保存时可提交；否则先展示方案并等待确认。

## 保存规则

- 仅允许新增下周需求、按原 ID 和 revision 受控补填空白下周需求、扩写未策划需求文字并添加确认产品，向已有需求回填空白策划字段，或使用专用工具修订已有策划标题正文及更新话题。补填仅写内容需求、确认产品和内容形式；保留原账号、栏目、日期与时间。
- 空白需求补填工具不接受已有文字、产品、模板、图片、策划或关联行动的需求；已有栏目提示或需求文字时使用下述受控扩写；已有需求的策划回填按下节执行；不得通过空白补填覆盖人工内容、删除、改排期、改配置或执行发布。版本冲突时重新读取并报告，不得转而新增重复需求。
- 同一批补填全部成功或全部回滚；失败后不拆批绕过冲突，先核对原因。
- 每个策划版本使用稳定且可追溯的 `idempotencyKey`。完全相同的重试复用原键；内容修改后使用新版本键。
- 需求中写清选题角度、核心信息、内容结构、画面或素材建议和关联产品理由；不虚构产品事实。
- 保存后分别报告新增或补填的记录 ID；若返回 `duplicate: true`，说明本次是安全重试，没有重复创建或再次补填。
- 没有选品、账号栏目、查看权限或保存权限时，停止写入并准确说明缺少什么。


## 已有需求的策划执行稿

- 原需求已有内容与产品时，用 `save_request_plans` 回填策划，不再调用空白需求补填，也不另建需求。
- 先按目标周分页读取排期，核对原需求 ID、revision、账号栏目、日期、时间及原需求。需要已有需求文字，原内容形式已选，策划字段尚为空且未关联行动。
- 展示原需求与策划的对应关系；用户当前明确授权保存后提交，否则先确认。
- 仅写 `title`（标题）、`copyText`（完整正文，评论区互动可分节标明）、`hashtags`（话题）、`imageScript`（封面及逐图结构）、`materialNeeds`（素材需求）。不得把执行稿覆盖到原 `notes`，不得修改产品、模板、形式或排期。
- 回填后进入策划候选状态，但不会自动发起行动或发布。已有策划或版本变化则整批拒绝，重新读取并报告，不绕过保护。安全重试使用同一幂等键。


## 已有策划的标题和正文修订

- 使用 `revise_request_copy`，不能用新增或空白回填工具替代。
- 先分页读取原记录，核对 ID、最新 revision、旧标题正文、关联产品和排期；结合用户提供的修订稿展示改动范围，用户当前明确授权修订保存后再提交。
- 仅传 `id`、`revision`、完整新 `title` 和完整新 `copyText`。必须保留正文中仍需要的评论区互动等内容；若修订稿只是片段，不得当成完整正文覆盖。
- 不修改原需求、产品、模板、形式、排期、话题、画面脚本及素材需求，不发起发布行动。
- 已进入行动或排期流程、原策划不完整、版本冲突时整批拒绝。冲突后重新读取并展示差异，不自动用新版本覆盖。
- 每版使用独立幂等键，相同请求重试复用原键。服务端记录操作者与修改前后文案，返回修订后的原记录ID和版本；保存后重新读取核对。

## 已有策划的话题更新

- 用户要求补充或修改已有策划话题时，使用 `revise_request_topics`；标题正文修订工具仍不修改话题。
- 先分页读取原需求 ID、最新 revision、旧话题和行动状态。展示逐篇对应关系；用户当前已明确授权写回即可提交。
- 仅传 `id`、`revision`、完整新 `hashtags`；保留需要的原话题。不得修改标题、正文、原需求、产品、模板、形式、排期、素材或发起行动。
- 已关联行动、进入执行流程、策划不完整或版本冲突时整批拒绝，重新读取并报告；不得拆批绕过或新增重复需求。
- 同一批次使用稳定幂等键，修订版更换键；返回话题修改前后审计，保存后重新读取核对。

## 扩写已有需求并关联产品

- 已有对应需求含栏目提示或文字、尚无策划时，使用 `expand_next_week_requests`，不能用空白补填或另建重复需求。用户已授权完成规划录入即包含这一步；先读取原ID、最新revision、原需求及品牌选品确认，保留原需求约束并形成完整扩写文本。
- 仅提交 id、revision、notes、workstationProductIds；产品数组表示要添加的确认产品，无新增传 []，已有产品不会被移除。工具不修改账号、栏目、形式、模板、素材或排期。
- 已有策划、关联行动、执行或版本冲突整批停止，重新读取并报告，不拆批绕过。已成功提交的同内容重试复用稳定幂等键。
- 扩写成功后重新读取记录及最新revision，再使用 `save_request_plans` 回填标题、正文、话题、画面脚本和素材需求；两步分别使用稳定幂等键。若策划回填失败，报告已扩写、尚未回填的真实状态，不重复扩写或新增需求。

正文允许用户明确选择空字符串 copyText:""；修订时会清空原正文。不可漏传、传null、非字符串或使用空白和占位文字替代，标题仍必填。
