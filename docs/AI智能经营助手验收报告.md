# AI智能经营助手验收报告

## 1. 验收结论

Phase 7 已完成，可提交，暂不发布。

本阶段建立的是“经营事实 → 可解释分析 → 人工确认 → 关键行动草稿”的决策辅助闭环，不是开放式聊天工具。系统不会自动修改产品、库存、财务、客户、销售连接或任务事实，也不会自动创建任务。

## 2. 已实现能力

- 新增一级模块“AI经营助手”。
- 支持公司、产品、连接、财务、供应链、客户六类经营分析。
- 保存每次分析的事实快照、来源表、规则版本、发现、建议和操作状态。
- 使用可解释规则引擎 `explainable_rules`；没有配置外部模型时不伪造大模型结论。
- 经营建议同时引用启用的行动标准和历史有效改善记录，供人工判断复用。
- 分析必须先人工确认，才能转为现有关键行动流程草稿。
- 关键行动草稿记录 `aiAnalysisId`、分析类型和对象，能够回溯原始分析。

## 3. 数据来源与可追溯性

|分析类型|主要事实来源|
|-|-|
|公司经营|经营驾驶舱、产品日快照、连接周期与体检事实|
|产品经营|产品经营分析、产品日快照、ERP日快照、财务分摊事实|
|连接经营|连接周期快照、成长分析、连接体检|
|财务经营|财务流水及报表计算结果|
|供应链|供应商、采购单、ERP库存事实|
|客户经营|客户档案、消费事实、跟进事实|
|企业知识|启用的行动标准、连接/产品历史有效改善结果|

每次生成均固化当时的 `sourceSnapshotJson` 和 `sourceReferencesJson`，后续事实变化不会覆盖历史分析依据。

## 4. 权限与安全

新增独立权限：

- `aiAssistant.view`
- `aiAssistant.analyze`
- `aiAssistant.confirm`
- `aiAssistant.createAction`

分析入口还会再次检查被分析模块的原权限。例如产品分析需要产品查看权限并验证产品数据范围，财务分析需要财务查看权限，客户分析复用客户数据范围。非全量数据范围用户只能查看和操作自己生成的分析记录。

旺店通密钥、用户密码和其他敏感配置均未进入分析快照、日志或前端。

## 5. 人工确认与事实保护

- 草稿分析不能直接创建改善行动。
- 确认操作记录确认人和确认时间。
- 转行动时必须选择有效目标，以及已绑定正式流程的启用行动标准。
- 只创建 `process_instances` 草稿，不自动创建任务。
- 不写入或重算历史经营事实。
