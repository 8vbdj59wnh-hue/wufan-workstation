# 链接中心 V3.3.1 平台链接经营导入验收报告

## 1. 验收结论

本次已把原“平台链接导入”和“平台经营数据导入”合并为统一类型：

```text
platform_link_operations
```

统一流程为：选择固定平台/店铺模板 → 上传 Excel → 模板解析与过滤 → 生成预览 → 人工确认 → 单一事务创建/更新链接档案并写入平台经营周期事实 → 保存导入批次。

四份真实样表均达到目标有效行数，重复文件未重复创建链接或经营事实。验证仅使用隔离数据库，未连接、修改或发布生产环境。

## 2. 实现范围

### 2.1 统一导入类型

- 新增用户入口 `platform_link_operations`（平台链接经营导入）。
- 原 `platform_links` 与 `platform_operations` 仅保留后台历史兼容定义，不再作为用户入口返回。
- ERP真实销售、ERP产品关系、ERP库存类型保持原模型与职责。

### 2.2 模板规则

模板版本的 `matchRulesJson` 统一承载：

- `fixedFields`：平台、店铺显示名、系统 `shopId`；
- `headerRow`：表头行；
- `sheetName` / `sheetNameContains` / `sheetNamePattern`：工作表选择；
- `dateRule`：字段日期、日期范围或工作表名日期；
- `rowFilters`：精确行过滤；
- `statusMap`：平台状态标准化；
- `periodType`：周期类型。

模板的字段映射继续版本化保存，不直接覆盖历史版本。

## 3. 预览与确认

上传阶段只写入导入批次和标准化预览行，不创建链接、不写经营事实。预览显示：

- 模板、平台、店铺；
- 数据周期；
- 原始行数、过滤后行数；
- 新增链接、更新链接、经营事实、异常数量。

确认阶段读取已验证预览行，在一个 SQLite 事务内完成：

1. 按 `shopId + platformGoodsId` 精确创建或更新 `sales_links`；
2. 创建或复用 `connection_profiles`；
3. 创建或复用 `connection_data_mappings`；
4. 写入 `connection_period_snapshots`；
5. 更新导入批次和行状态。

事务中的意外错误会整体回滚，不会产生半批次写入。

## 5. 周期事实唯一键评审

### 5.1 当前风险

原唯一键为：

```text
sourceType + externalId + periodStart + periodEnd
```

`externalId`是平台商品ID，不能保证跨平台、跨店铺全局唯一。不同店铺在同一周期出现相同商品ID时，原唯一键会错误阻止第二条真实事实。

### 5.2 建议并已编码的目标键

```text
sourceType + salesLinkId + periodStart + periodEnd
```

`salesLinkId`已经指向由 `shopId + platformGoodsId` 唯一确定的销售链接，因此能够保留店铺维度，同时不改变链接身份模型。

### 5.3 迁移方案

迁移代码已加入项目，但本次没有在生产执行：

1. 发布前在线备份并记录SHA-256；
2. 检查目标键是否存在历史重复；
3. 删除旧索引 `idx_connection_period_snapshots_external_period`；
4. 创建新索引 `idx_connection_period_snapshots_link_period`；
5. 执行 `integrity_check` 与 `foreign_key_check`；
6. 异常时以数据库备份整体回滚，不尝试删除历史经营事实。

隔离库迁移结果：新唯一索引创建成功，旧索引已移除。
