# 极简工作站全面健康检查与第一阶段整改报告

## 结论

系统核心业务和数据库当前可用，但尚未达到“无需治理”的状态。本轮确认并修复了 4 个低风险高收益问题：管理驾驶舱误加载全局快照、查询任务波次时隐式写入、附件匿名公开访问、登录缺少失败限流。

本阶段没有删除业务数据、数据库表、生产发布历史或备份。

## 本次已修复

1. 管理驾驶舱的 `dashboardManagement` 路由纳入轻量模块，不再回退到 `/api/data` 全局快照。
2. `GET /api/task-waves` 变为纯读取，不再因为拥有 `tasks.view` 而生成任务波次。生成能力仍由明确写操作和后台任务承担。
3. `/uploads` 从匿名静态资源改为登录用户可读；API 令牌和 24 小时附件令牌分离，不可交叉使用；附件响应增加私有缓存、禁止 Referer 外泄和 MIME 嗅探防护。
4. CORS 从全开放改为同主机常用端口或显式白名单。
5. 登录失败增加按 IP + 账号的内存限流，成功登录后清除计数。
6. 运行时支持通过绝对路径配置共享附件目录和持久登录密钥，避免为每个工作树复制大量附件，也避免发布目录变更导致登录态无故失效。

## 系统垃圾候选（未删除）

- 生产发布目录约 78 GB、63 份，是当前最大的可治理对象，但必须保留当前版、安全回滚版和审计所需发布记录。
- 生产备份约 7.4 GB；需要按时间、发布链和可恢复验证建立保留周期，不能仅因文件大就删除。
- 本机可确认的完全相同数据库副本共约 1.6 GB；删除前仍需核对是否被服务、脚本或报告引用。
- 本机已合并且干净的工作树约 7.7 GB，另有 4 条可剪枝的 Git worktree 元数据。
- 上述项目全部是“清理候选”，不是已授权删除清单。
