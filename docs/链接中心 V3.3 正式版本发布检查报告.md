# 链接中心 V3.3 正式版本发布检查报告

检查日期：2026-08-03

功能基线：`ef93c4e refactor: polish link center v3 ui`

检查范围：链接中心 V3 Phase1～Phase4、V3.1、V3.2

检查性质：只读整理、发布准备；未发布、未修改业务数据。

## 一、发布结论

当前功能链路、数据库迁移幂等性和数据完整性检查通过，但**暂不具备正式发布条件**。

阻断原因：运营人员的数据范围控制尚未完整覆盖历史分析接口。主列表、经营驾驶舱、我的链接、链接医院已经按负责人过滤；但成长排行、管理汇总、待关注体检、改善汇总及部分按连接 ID 查询的历史接口仅验证 `links.view/products.view`，未再次验证目标连接是否属于当前负责人。正式发布前必须补齐服务端所有权校验并重新验收普通运营账号。

本报告不修改权限逻辑，符合 V3.3“只整理、检查、发布准备”的限制。

## 二、最终模块结构

经营链接中心当前一级入口顺序为：

1. 经营驾驶舱；
2. 我的链接；
3. 链接资产；
4. 链接医院；
5. 数据中心。

导航名称、排列和页面渲染分支已统一。连接详情继续使用兼容路由 `#connectionCenter/<connectionId>`；产品和连接保留双向跳转。数据导入、经营数据导入、字段映射和待关联数据已收口到数据中心内部入口。

链接详情顺序为：基础信息、经营概览、平台表现、ERP真实销售、SKU销售分析、产品关联、库存供应、健康状态、链接医院、改善记录；经营动作、经营趋势和链接对标作为既有扩展能力继续保留。

## 三、当前功能清单

### 经营驾驶舱

- 经营总览：链接、销售额、利润、风险、诊断、治疗；
- 核心链接：按 ERP 销售额、利润和销量排序；
- 风险链接：复用健康分析及经营变化；
- 增长链接：复用销售、利润、流量和转化变化；
- 平台分析：按平台聚合链接、销售与利润；
- 产品渠道分析：按链接 → SKU → 产品聚合渠道贡献；
- 日、周、月趋势入口。

### 我的链接

- 当前负责人范围过滤；
- 管理员全量视角；
- 关注和取消关注；
- 向好、风险及关注筛选；
- 销售、流量、转化、利润风险提醒；
- 今日待诊断、治疗中、观察中事项。

### 链接资产

- 列表和卡片视图；
- 平台、店铺、产品编码、负责人、健康、销售、利润、产品关系、SKU数量及状态筛选；
- 经营排序、字段排序和字段显示配置；
- 链接详情及产品双向跳转。

检查差距：当前“产品编码”输入框属于定向筛选，并没有覆盖链接名称、商品ID和店铺的统一搜索。因此 V3.3 验收项中的“搜索”尚未完整实现；本轮按禁止新增功能的要求只记录，不在发布准备任务中补开发。

### 链接医院

- 诊断区、治疗区、观察区；
- 异常仅提醒，不自动进入诊断；
- 负责人或管理员人工加入诊断；
- 复用关键行动和任务体系；
- planned → executing → observing → effective/failed 状态流转。

### 数据中心

- 平台链接导入；
- 平台经营数据导入；
- ERP真实销售导入；
- ERP产品关系导入；
- ERP库存导入；
- 导入模板及模板版本；
- 字段映射；
- 导入批次、导入记录和异常记录；
- 文件哈希及事实唯一约束保证重复导入幂等。

## 四、权限检查

### 已确认

- 管理员：`isAdminUser` 路径读取全部连接；
- 我的链接：普通人员按 `connection_profiles.ownerId` 过滤；
- 核心列表：`listConnectionCoreProfiles` 按负责人过滤；
- 驾驶舱：`getConnectionBusinessCockpit` 按负责人过滤；
- 链接医院：`getConnectionHospital` 按负责人过滤；
- 加入诊断：服务端限制为负责人或管理员；
- 数据导入：继续使用 `links.import`，并保留旧 `products.edit` 兼容权限。

### 发布阻断项

以下接口或汇总尚未完整应用负责人数据范围：

- `/api/connection-growth-rankings`；
- `/api/connection-management/overview`；
- `/api/connection-health-records/attention`；
- `/api/connection-improvements/summary`；
- `/api/connections/:id`；
- `/api/connections/:id/period-snapshots`；
- `/api/connections/:id/growth-analysis`；
- `/api/connections/:id/health-records`；
- `/api/connection-improvements?connectionId=...`；
- 经营动作、对标等按连接 ID 的接口需要统一复核所有权。

风险：普通运营账号可能看到全局汇总，或在已知连接 ID 时越过负责人范围读取非本人连接的附属信息。必须在后端统一增加连接可见范围校验，不能只依靠前端隐藏。

## 七、性能检查

在包含 981 个连接档案的隔离库上执行服务层读取：

| 页面/服务 | 读取耗时 |
|---|---:|
| 链接资产管理员列表 | 987.24 ms |
| 单连接核心详情 | 4.55 ms |
| 管理员经营驾驶舱 | 46.85 ms |
| 管理员我的链接 | 39.24 ms |
| 管理员链接医院 | 13.12 ms |

驾驶舱、我的链接和医院使用批量查询与内存映射，不存在前端逐链接请求。详情页为单连接定向查询。

已知性能风险：`listConnectionCoreProfiles` 虽批量读取产品和经营指标，但仍对每条连接单独执行 SKU/产品数量统计。981 条连接时列表约 1 秒，属于数据库逐条查询，应在不改变返回结构的前提下改为一次 `GROUP BY salesLinkId` 批量统计。该项不是数据正确性问题，但连接数量继续增长时会影响资产页加载。

## 十、风险点

1. **发布阻断：负责人数据范围未覆盖全部历史接口。**
2. **功能差距：链接资产没有覆盖名称、商品ID和店铺的统一搜索。**
3. **性能观察：链接资产列表存在逐连接关系计数查询。**
4. 生产日常库尚未执行 V3 新表迁移；必须先做生产备份和迁移预演。
5. V3 真实销售事实在隔离验收库样本较少；正式启用导入后需观察实际文件规模和导入耗时。
6. 浏览器人工登录验收是正式发布脚本之外的强制步骤，不能以语法检查代替。

## 十一、建议发布步骤

当前不得直接发布。先完成权限阻断项修复与普通运营账号回归，然后：

1. 确认 Dev-01 `main` 干净、目标提交为完整快进链；
2. 执行 `npm run check`、`git diff --check`；
3. 生成 `frontend` 或实际分类匹配的离线发布包并验证 `SHA256SUMS`；
4. 将发布包传到 Server-01；
5. 在 Server-01 先执行 `release-from-package.sh --dry-run`；
6. 正式执行时创建生产 SQLite 在线备份和代码证据；
7. 仅在备份副本执行迁移预演两次，核对核心表数量；
8. 执行发布前健康检查；
9. 使用 `git merge --ff-only` 更新目标版本；
10. 按分类重启需要更新的服务；
11. 执行发布后健康、完整性、外键和数量检查；
12. 管理员与普通运营账号分别进行浏览器人工验收；
13. 验收通过后创建生产标签并保存 manifest。

## 十二、回滚方案

1. 发布前保存目标提交、生产提交、PM2状态、生产数据库在线备份及其 SHA-256；
2. 若仅前端/后端代码异常且尚无迁移和发布后业务写入，使用受控的前向修复或经审核的上一版本切换；
3. 若迁移已经执行但业务数据没有新写入，先停止写入并根据 manifest 评估代码与数据库的配套回退；
4. 若发布后存在业务写入，禁止直接覆盖生产数据库，应优先前向修复并保留新数据；
5. 只有确认无需要保留的发布后业务写入、备份校验通过且得到明确审批后，才允许人工恢复数据库；
6. 回滚后重新执行服务健康检查、SQLite完整性检查、外键检查和核心页面验收。

- 数据保护：通过；
- 迁移幂等预演：通过；
- 基础性能：有观察项；
