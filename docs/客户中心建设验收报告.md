# 客户中心建设验收报告

## 一、建设结论

客户中心已形成独立客户资产管理层，覆盖客户档案、消费记录、标签、生命周期、跟进维护和价值分析。未修改产品、销售链接、ERP、任务或现有会员系统的数据结构与业务逻辑。

## 二、业务边界

- 客户档案使用 `businessType` 强制区分 `ecommerce`（电商）与 `local_life`（本地生活）。
- 消费记录必须与客户业务类型一致，跨类型写入会被拒绝。
- 会员关系只保存 `memberExternalId` 外部引用，不复制会员资料，不改写会员状态。
- 产品和销售链接仅作为可选消费来源引用，不改变其身份。

## 三、新增数据结构

- `customers`：客户档案、来源、生命周期、隐私级别与会员外部引用。
- `customer_consumptions`：消费事实及可选产品/销售链接关系。
- `customer_tags`：用户属性、消费偏好、购买行为和生命周期标签。
- `customer_tag_relations`：客户标签关系。
- `customer_followups`：客户维护、营销和服务跟进。

全部迁移均使用幂等建表/索引语句，未修改核心业务表。

## 四、客户价值与生命周期

- 客户价值：累计消费金额、消费次数、最近消费时间。
- 高价值：人工标记或累计消费达到首版阈值。
- 活跃：存在多次有效消费。
- 流失风险：最近消费超过 90 天。
- 新客户和沉默客户保留人工管理状态。

自动判断只作为展示分析，不回写和覆盖客户人工生命周期字段。

## 五、权限与隐私

新增独立权限：

- `customers.view`
- `customers.manage`
- `customers.maintain`
- `customers.analyze`

客户权限不回退复用产品权限。普通查看接口对手机号和邮箱脱敏；只有客户管理权限可读取完整联系方式。管理员默认具备新权限，其他账号必须显式授权。

读取和写入同时应用现有数据范围：本人范围只访问自己负责的客户，部门范围只访问本部门负责人客户，全部范围才可访问全公司客户；已知客户 ID 不能绕过对象范围校验。
