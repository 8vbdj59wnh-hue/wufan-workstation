# 链接中心 V3.3 发布阻断修复验收报告

## 一、验收结论

本次仅修复 V3.3 发布检查确认的三个阻断项：服务端连接可见性、链接资产统一搜索、链接资产列表聚合性能。未新增业务功能，未修改数据模型、连接身份、经营事实或链接医院流程。

结论：三个发布阻断项均已修复，验证通过，可进入后续发布检查。

## 二、统一连接权限校验

- 新增统一的服务端连接可见性校验：管理员可访问全部连接；普通运营仅能访问 `connection_profiles.ownerId` 等于当前人员 ID 的连接。
- 所有 `/api/connections/:id` 详情及附属资源入口统一接入校验，包括经营详情、周期快照、成长分析、体检、动作、诊断和对标数据。
- 体检改善行动、改善项目创建与更新会先由体检记录或改善项目反查连接，再执行同一可见性校验。
- 成长排行、经营概览、待关注体检、改善列表与改善汇总按当前人员范围聚合，不再向普通运营返回其他负责人的数据。
- 内部对标候选、内部对标保存和历史内部对标比较同样受负责人范围约束。

隔离库验证结果：

- 普通运营读取自己负责连接：通过。
- 普通运营读取其他负责人连接：返回 403，拒绝访问。
- 管理员读取全部连接：通过。
- 负责人范围内的排行和汇总：未发现跨负责人数据。

## 三、链接资产统一搜索

链接资产顶部增加统一搜索框，支持以下字段：

- 链接名称；
- 商品 ID；
- 店铺；
- 平台；
- 产品编码。

统一搜索与原有平台、店铺、产品编码、负责人、健康状态、经营状态、产品关联和 SKU 数量筛选采用共同的交集过滤逻辑。

验证结果：名称、商品 ID、店铺、平台、产品编码五类搜索均通过；不存在的关键字不会产生错误结果。

## 四、列表性能优化

链接资产列表原先在遍历每条连接时分别查询 SKU 数量和产品数量，现已改为：

1. 一次收集当前可见连接的 `salesLinkId`；
2. 一次批量分组聚合 `sales_link_skus`；
3. 通过映射回填每条连接的 `skuCount` 和 `productCount`。

返回字段和前端展示结构保持不变。连接详情页的单连接查询不属于列表逐条查询，保持原逻辑。

隔离库 980 条连接验证结果：

- 列表返回数量：980；
- SKU 数量与独立 SQL 聚合结果：一致；
- 产品数量与独立 SQL 聚合结果：一致；
- 本次本机加载测量：约 46ms；
- 列表映射过程：不存在逐连接 SKU/产品统计查询。
