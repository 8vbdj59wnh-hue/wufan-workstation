1. `src/permissions.js` 的权限清单没有 `links` 和 `supplyChain` 权限组，也没有对应的模块访问项。
2. 页面和服务端已经引用 `links.view/manage/import/health/improve`、`supplyChain.view/manage/purchase/quality`。
3. 权限标准化只保留清单中声明的字段，因此历史数据或人工配置中的上述业务权限会被丢弃。
4. 链接与供应链导航、页面按钮、API 中间件和 AI 经营分析通过 `products.view/edit` 现场回退，导致产品权限与两个业务域无法独立授权。

## 四、实现内容

### 4.1 独立权限定义

新增模块访问权限：

- `modules.links`
- `modules.supplyChain`

新增链接中心权限：

- `links.view`
- `links.manage`
- `links.import`
- `links.health`
- `links.manageHealth`
- `links.improve`

新增供应链中心权限：

- `supplyChain.view`
- `supplyChain.manage`
- `supplyChain.purchase`
- `supplyChain.quality`

其中 `links.health` 负责体检读取，`links.manageHealth` 负责创建和管理体检，避免只读兼容角色获得体检写权限。

### 4.2 历史权限兼容

旧权限数据在完全缺少新业务域边界时，由权限标准化层执行一次兼容映射：

| 历史产品权限 | 兼容获得的新权限 |
| --- | --- |
| `products.view` / `modules.products` | `links.view`、`links.health`、`supplyChain.view` 及相应模块访问 |
| `products.edit` | `links.manage`、`links.import`、`links.manageHealth`、`links.improve`、`supplyChain.manage`、`supplyChain.purchase`、`supplyChain.quality` |

兼容规则还保留历史上可能手工写入的部分 `links.*` 字段；历史显式 `links.health` 在未配置新字段时继续兼容体检管理能力。

一旦权限数据显式包含 `modules.links/modules.supplyChain` 或对应业务域的 `view` 边界，系统即视为新权限模型，不再从产品权限回退。这样可以配置“有产品权限但无链接/供应链权限”以及“只有链接或供应链权限”的角色。

### 4.3 前后端权限守卫

- 链接中心导航只检查 `links.view`。
- 供应链中心导航只检查 `supplyChain.view`。
- 链接页面管理、导入、体检、改善入口只检查链接权限。
- 供应链页面供应商、采购、品质操作只检查供应链权限。
- 服务端链接和供应链 API 中间件只检查独立业务权限。
- AI 经营分析的链接、供应链证据读取只检查对应独立业务权限。
- 旧 `products.*`、`modules.products` 及其他既有权限定义全部保留。
