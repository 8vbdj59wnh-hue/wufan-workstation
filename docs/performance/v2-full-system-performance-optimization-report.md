# 《极简工作站全系统流畅性优化报告》

## 1. 范围与基线

本次以当前生产提交 `9014723c11fc5e0eb97647b1d9262cc76b6d24d4` 为代码基线，使用生产 SQLite 在线备份生成的只读副本进行测试。备份副本大小为 988,372,992 字节，SHA-256 为 `28b079a07cdad1ee3c89ec7f09404c1652b39a6c6b2a3d53a29e463f1d5fc292`，`integrity_check=ok`，外键检查无异常。

数据规模：目标 14、任务 7,320、关键行动实例 1,304、工作计划 1,243、产品 2,958、ERP SKU 6,906、经营链接 10,006。已退役的客户中心、供应链中心和 AI 经营助手未纳入优化范围。

生产服务器只读基线：后端 Node 进程内存约 192MB、CPU 约 0.1%；无 swap；数据盘使用率约 50%；当前网络往返抽样为 7.7–78.5ms，平均 40.6ms。生产副本 SQLite 主键探针 P95 小于 1ms。

| `/api/data` | 29,436,640B | 设置、模板、行动标准等低频页面仍走全系统快照 | P0 |

| 模板中心 | 29,436,640B | 为显示“引用次数/最近使用”加载全部任务和关键行动实例 | P0 |
| 设置 | 29,436,640B | 未使用模块级启动契约 | P0 |
| 前端入口 | 8 个低频页面源码合计 494,399B 同步进入入口依赖图 | 页面模块静态导入 | P1 |

## 3. 实际修改

### 3.1 经营链接列表

- 将平台有效链接统计从“对每个链接执行相关查询”改为“一次批次范围聚合 + 一次链接总量聚合”。
- 先锁定最新完整平台批次，再只解析该批次关系；没有改变链接有效性、评级、关系或权限语义。
- `EXPLAIN QUERY PLAN` 确认按 `batchId` 使用 `idx_platform_goods_excel_rows_action`，链接关联使用 `sales_links` 主键覆盖索引。
- 为链接列表和启动接口增加 `Server-Timing`，便于后续区分数据库、数据范围和附加计算耗时。

### 3.2 通知启动摘要

- 新增通知摘要读取能力：启动时只返回最近 12 条和独立未读总数。
- “全部已读”改为一次服务端批量更新，不再由前端逐条写入。
- 从所有通用启动数据中移除全量通知，单条已读后只局部更新当前对象和未读计数。

### 3.3 设置与模板中心

- 设置、模板中心、行动标准建立明确的模块启动资源契约，不再回退 `/api/data`。
- 模板引用数和最近使用时间改为服务端聚合结果；前端不再为了这些统计加载 7,320 条任务和 1,304 条关键行动实例。
- 使用生产副本逐模板比对新聚合结果与原有全量计算结果，计数和最近使用时间一致。

### 3.4 前端按模块加载

- 驾驶舱、目标、关键行动、行动标准、模板中心、财务中心、设置改为进入模块时动态加载。
- 保留统一加载失败、重试和导航竞态保护；没有改动页面业务逻辑。
- 8 个页面模块共 494,399B 源码退出同步入口依赖图。

## 4. 优化前后性能

生产副本数据读取和服务层均在同一开发机、同一代码进程下测量；P95 样本量较小，作为本次回归基线，不代替长期生产监控。

| 页面/接口 | 优化前 | 优化后 | 结果 |
|---|---:|---:|---|
| 经营链接列表 50 条 | >30,000ms；压力探针 >90,000ms | 92,758B；P50 116–248ms；P95 193–759ms | 达标，且只返回 50 条 |
| 产品列表 50 条 | 既有分页链路 | 79,036B；P50 177–433ms；P95 456–744ms | 无回退，P95 <1s |
| 设置首屏 JSON | 29,436,640B | 213,541B | 减少 99.3% |
| 模板中心首屏 JSON | 29,436,640B | 987,337B | 减少 96.6% |
| 最大用户通知启动数据 | 1,904,552B | 5,790B（12条 + 未读数） | 减少 99.7% |
| 驾驶舱/产品/财务通用启动 | 2,743,231B | 838,662B | 减少 69.4% |
| 行动标准启动 | 29,436,640B | 17,156,705B | 减少 41.7%，仍需继续拆分 |
| 关键行动启动 | 19,405,925B | 17,501,356B | 减少 9.8%，仍需继续拆分 |
| 目标中心启动 | 28,011,073B | 26,106,504B | 仅移除通知，仍属 P0 |

模板中心服务端聚合读取 P50 约 228ms；设置模块资源读取约 1–2ms。浏览器实测全部链接仅生成当前页 50 行，产品列表仅生成当前页 30 行，任务列表当前页生成 27 张卡片。

## 5. 被移除的全量加载

1. 设置、模板中心和行动标准不再调用 29.4MB 的 `/api/data` 全局快照。
2. 所有模块启动不再附带完整通知历史。
3. 模板中心不再读取完整任务和关键行动实例来计算引用统计。
4. 链接列表不再为当前页请求触发逐链接的平台导入行相关扫描。
5. 8 个大型/低频前端页面不再由系统入口同步加载。
6. 通知全部已读不再执行 N 次前端串行请求。

## 6. 仍然存在的性能瓶颈

| 位置 | 当前证据 | 最小后续方向 |
|---|---|---|
| 目标中心 | 26.1MB，浏览器仍生成大任务表 | 独立改为目标摘要、服务端分页、详情按需；该改造涉及较多页面交互，未混入本次低风险提交 |
| 关键行动 | 17.5MB，日历生成较大 DOM | 服务端日期窗口摘要，任务/节点/结果进入详情后读取 |
| 行动标准 | 17.2MB，仍带任务、实例、计划 | 列表只返回模板摘要，单个标准详情按需读取 |
| 模板中心 | 数据已降到 1MB 内，但卡片仍一次渲染全部资产 | 数据继续增长时增加服务端分页或虚拟列表 |
| 经营驾驶舱 | 部分分布图仍会生成较多链接分组 | 将统计完全改为聚合 DTO，列表仅在钻取时加载 |

这些遗留点已明确记录，没有用跨模块重构或业务模型调整扩大本次范围。

## 7. 服务器与迁云判断

当前生产后端内存约 192MB、CPU 约 0.1%、无 swap，SQLite 主键读取小于 1ms。原链接列表超过 30 秒的根因是查询形态，代码优化后在同一硬件上降到 1 秒以内。因此当前服务器不是本轮卡顿的主要瓶颈。

现阶段没有仅为性能而迁云或升级服务器的必要。迁云仍可从高可用、容灾、运维和公网访问角度单独评估，但不能替代目标中心、关键行动和行动标准剩余的按需加载改造。
