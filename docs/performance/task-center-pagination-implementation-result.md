# V2-PERFORMANCE-009 任务中心分页加载改造验收报告

## 1. 修改范围

- 新增任务中心服务端分页接口：支持今天、我的、逾期、全部，以及页码、每页数量、关键词、筛选和排序；默认每页 50 条，最大 100 条。
- 权限、负责人、状态、逾期、行动编码和模板编码条件均在服务端分页前执行。
- 任务列表只返回列表摘要；提交结果、附件、动态、流程上下文和产品关系改为打开详情时加载。
- 任务波次不再随任务中心启动加载，只在进入“任务波次”页签后请求。
- 批量状态操作不再返回全局数据快照，操作后只刷新当前任务页。
- 任务中心启动快照移除完整任务、流程实例、工作计划、内容排期、行动产品和通知数据。

## 2. 性能变化

优化前基线：

- 任务中心启动快照：15,534,553 bytes。
- 任务波次：217,935 bytes。
- 合计：15,752,488 bytes，约 15.75MB。

隔离验证结果：

- 轻量启动快照：80,286 bytes。
- 当前页任务列表：4,962 bytes。
- 首次数据合计：85,248 bytes，约 0.085MB。
- 列表接口 10 次测量：P50 2.4ms，P95 17.8ms。

说明：隔离生产副本当前符合筛选条件的任务量较少；性能阈值脚本会在更大数据副本上继续验证 `<1MB / P50<500ms / P95<1s`。

## 3. 查询链变化

原链路：全量任务、流程、工作计划、通知和波次进入前端，再由前端筛选与展示。

新链路：服务端权限与业务条件过滤 → 排序 → 分页 → 当前页摘要及必要上下文 → 详情按需加载。

波次链路：进入任务波次页签 → 加载波次；任务列表仅返回当前页涉及的波次摘要。

## 4. 数据一致性与回归

- 今天视图继续包含今日到期或正在执行的未完成任务。
- 我的、逾期、全部视图口径保留。
- 关键词继续覆盖任务名称、任务编码、行动编码、模板编码。
- 状态、部门、负责人、执行人、逾期、完成及取消筛选在分页前生效。
- 任务详情保留原渲染和操作逻辑，仅改变加载时机。
- 完成、取消、恢复及批量状态操作只刷新当前筛选页，不触发 `/api/data`。
- 波次操作保持原业务服务，本阶段未修改状态机、流程引擎和数据库结构。

## 6. 风险说明

- 任务中心旧页面仍有较多历史交互逻辑；本次采用兼容摘要和详情上下文水合，避免重写业务逻辑。
- 更大任务量下的 P50/P95 需要在正式发布预演所用生产副本上再次运行自动性能验证。
- 流程进度和库存清仓属于独立页签，本阶段没有改变其业务数据加载口径。
