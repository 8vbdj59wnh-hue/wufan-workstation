## 1. 14.77 秒问题的真实时间线与根因

临时测量将“点击产品中心 → 页面可交互”拆分至路由、模块、bootstrap、产品 API、数据处理、HTML、DOM、图片和事件阶段。受控冷启动复现中，原链路总计 20.538 秒，其中：

|阶段|时间点/耗时|
|---|---:|
|T0 点击产品中心|0 ms|
|T1 路由开始|0.5 ms|
|T2 产品模块完成加载|13.9 ms|
|产品 bootstrap 发出|14.0 ms|
|产品 bootstrap 收到响应|14,884.5 ms|
|T3 产品经营 API 发出|14,866.8 ms|
|T4 产品经营 API 收到响应|20,507.6 ms|
|T5 JSON 解析和数据处理完成|20,508.8 ms|
|T6 HTML 生成完成|20,515.2 ms（生成 6.2 ms）|
|T7 DOM 写入完成|20,517.4 ms（写入 2.1 ms）|
|T9 事件绑定完成|20,518.0 ms|
|T10 图片初始化并可交互|20,537.9 ms|

根因不是产品页前端处理。首页进入时同时触发了三个同步重型读取：

|首页请求|生产副本服务耗时|响应大小|
|---|---:|---:|
|旧经营概览|5.316 秒|38,464 B|
|销售经营驾驶舱|4.240 秒|1,091,211 B|
|经营异常|4.031 秒|1,621,083 B|

三个请求累计占用同步 SQLite/Node 执行约 13.6 秒，其中旧经营概览和经营异常并未进入当前首页渲染。用户已经离开首页后，它们仍继续运行，导致产品 bootstrap 和产品经营 API 排队。此前观察到的约 10 秒额外等待正来自这条隐藏串行链，而不是产品经营 API 完成后的 DOM 处理。

## 2. 实际修复

1. 首页停止自动请求未渲染的旧经营概览和经营异常；当前可见的销售驾驶舱延迟启动，并在延迟结束时再次确认首页仍是当前路由。用户直接切换模块时不再启动已不可见的首页重型读取。
2. 产品 bootstrap 只加载当前页面实际需要的人员目录；产品列表、详情、经营事实继续走专用分页/按需接口，不读取 `/api/data` 或 Legacy 全量快照。
3. 产品子视图已有数据时只恢复现有状态，不再无条件刷新产品经营、驾驶舱、沙盘、新品和清仓数据。
4. 产品沙盘增加前端 `visibleCount`：首次最多 100 张，点击“加载更多”每次增加 100 张。
5. ERP SKU 详情新增明确的“编辑产品”入口，直接进入 ERP SKU 经营扩展；保存后同时失效产品经营读模型、SKU 列表缓存和服务端 V2 列表缓存。
