## 一、执行结论

V3 三步主链可以替代“正常商品关系”的人工建立流程，但用户最初提出的三步模型需要补上三个边界，才能成为可上线架构：

1. 旺店通组合装父编码是 `goods.Suite.search` 的 Suite 身份，不是 `erp_skus` 中的单品 SKU。本次 3,479 个 Bundle 父编码中，存在于 `erp_skus` 的数量为 **0**。因此 Sales Object 实体不能直接删除，但可以降级为由平台货品 + 旺店通 Suite 自动生成的投影。
2. 链接利润表的组合装行已经按组件拆成多行；父组合装编码必须来自平台货品表，不能把利润表“商家编码”直接当作组合装父编码。
3. 利润表包含 `0013`、`0016` 等非商品财务行。公司总销售额不能只写成 `Single + Bundle`，必须是 `Single + Bundle + 非商品/未解析金额`。本次没有发生组件展开造成的金额重复，但存在第三类金额。

商品相关销售事实共 3,080 组，其中 3,030 组完整闭环，**商品主链闭环率为 98.3766%**。若把 24 组非商品财务事实也放进分母，整体闭环率为 97.6160%。

## 十二、Sales Object 与 Product Structure 的最终判断

### Sales Object

Sales Object **可以完全降级为自动投影，不能完全删除实体语义**。原因是 Bundle 父编码属于旺店通 Suite，不属于 `erp_skus`；平台 Link SKU 仍需要指向一个可承载父销售额、有效期和 BOM 版本的销售对象。

建议：

`Link SKU → 自动 Sales Object（source=platform_goods/wangdian_suite） → effective-dated BOM → ERP SKU → Product`

人工审批只处理冲突、缺失、历史版本无法解释等异常。

### Product Structure

旧 Link Product Structure 可以退出正式运行链路，但必须先完成：

1. 把当前生效结构与历史有效期归档；
2. 为旺店通 BOM 建立有效期/版本快照；
3. 用历史销售日期选择对应 BOM，而不是永远使用当前 BOM；
4. 完成 9 个真实 BOM/销售证据不一致对象的核对。

## 十三、推荐 V3 正式主链

```text
平台货品表
  → Store / Link / Link SKU / sourceCode
  → 旺店通按 sourceCode 查询
      → Goods API 命中：Single
      → Suite API 命中：Bundle + BOM
  → 自动生成 Sales Object 投影及有效期 BOM
  → Component ERP SKU → product_erp_mappings → Product

链接利润表
  → 原始事实金额唯一保存
  → 0013/0016 进入非商品财务分类
  → 通过 Link + Link SKU 获取父 Sales Object
  → Bundle 只展开物理数量，不复制销售额/利润
```

## 十四、十个核心问题的回答

1. **仅用平台货品表 + 旺店通 API + 利润表，能否建立商品和销售主链？** 能，但必须补“非商品财务分类”“Sales Object 自动投影”“历史 BOM 有效期”三项。
2. **闭环覆盖率？** 商品事实 98.3766%；含非商品事实的整体口径 97.6160%。
3. **哪些旧逻辑可删除？** Legacy Mapping 正式读取、人工正常关系审批、旧 Combo、Manual Binding 正式写入、销售数据推断父关系；均应经过只读兼容与归档窗口后退出。
4. **哪些异常仍需人工？** 16 个旺店通无法确认编码、1,037 个空平台编码、27 个本期销售但平台关系缺失 Link SKU、9 个 BOM/销售证据不一致 Link SKU、1 个 Single 组件冲突、1 个 Product Mapping 缺失、2 个单组件×1可疑结构。
5. **Sales Object 能否完全降级为自动投影？** 可以；但其实体语义不能删除，因为 Suite 父编码不属于 `erp_skus`。
6. **Product Structure 能否退出正式链路？** 可以，前提是旺店通 BOM 有版本/有效期并完成历史归档。
7. **旺店通能否停止全量同步，改为按经营 ERP 集合查询？** 关系识别可以；库存和商品主档仍应保留增量同步，不建议停止所有 API 同步。
8. **Product 销量能否准确拆成直接销量和 Bundle 贡献量？** 绝大多数可以；本期 440/453 个 Bundle 日事实准确，13 个不一致事实必须暂缓贡献推断。
9. **是否存在销售额/利润重复统计？** 本演练无重复，组件新增金额为 0；但公司总额还包含非商品/未解析金额，不能只加 Single 和 Bundle。
10. **V3 迁移需保留哪些兼容层？** Sales Object ID 兼容门面、有效期 BOM、Legacy 只读审计、历史 Product Structure 归档、旧 Resolver 诊断比较、非商品事实分类。

## 十六、最终结论

真实数据证明 V3 的方向成立：正常商品关系不需要人工建立，主关系可以由平台货品和旺店通 API 自动形成。与此同时，真实数据也否定了两个过度简化假设：组合装父编码不是单品 ERP SKU；公司金额不只由 Single 与 Bundle 两类商品事实组成。

建议下一阶段不是直接删除旧表，而是先实现“自动 Sales Object 投影 + 有效期 BOM + 非商品事实分类 + 影子对比”，达到全量同周期验证后，再冻结 Legacy 写入和 Product Structure 正式读取。
