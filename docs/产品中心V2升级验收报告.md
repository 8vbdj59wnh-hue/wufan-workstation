## 1. 升级结果

产品中心已在不改变产品、SKU、ERP、销售连接既有身份关系的前提下，补充经营概览、经营分析、生命周期、经营体检、问题发现和改善行动闭环。产品问题仍通过现有关键行动（`process_instances`）及任务体系推进，没有建立第二套执行模型。

## 2. 功能验收

| 能力 | 验收结果 |
|---|---|
| 产品经营首页 | 展示产品总量、生命周期分布、成长产品和风险产品 |
| 产品列表 | 复用原列表与筛选，补充生命周期、销售额、增长、净利润和库存字段 |
| 产品卡片 | 补充销售额、增长、净利润和库存经营指标 |
| 产品经营详情 | 展示销量、增长、库存周转、利润及关联连接转化变化 |
| 生命周期 | 支持六阶段受控变更并保存变更历史；旧状态统一显示为“待归类”，不自动迁移 |
| 经营体检 | 使用固定规则识别销售下降、库存积压、缺货、低利润和转化下降 |
| 改善闭环 | 产品问题可创建关键行动草稿，并记录产品改善项目及前置指标 |
| 权限 | 查看沿用 `products.view`，体检、生命周期和改善操作沿用 `products.edit` |

## 3. 数据来源

- 销量与库存：复用 `product_daily_snapshots` 和 `erp_fact_snapshots`。
- 销售额、成本、费用与利润：复用已确认或已审核的 `finance_entries`。
- 连接流量与转化：复用 `connection_period_snapshots`，通过正式 `sales_link_skus` 产品关系汇总。
- 产品主数据：继续以 `products` 为产品业务对象；没有修改 SKU 或 ERP 映射规则。

## 4. 新增数据结构

- `product_lifecycle_events`：产品生命周期变更历史。
- `product_health_records`：指定经营事实快照上的体检结果。
- `product_issues`：体检发现的结构化经营问题。
- `product_improvements`：问题、关键行动及改善结果之间的关系。

迁移均通过 `CREATE TABLE/INDEX IF NOT EXISTS` 实现，可重复执行；没有修改 `products`、`sales_links`、`tasks` 等核心表结构。
